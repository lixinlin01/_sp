# 系統程式期末專題報告：基於 Linux Raw Socket 之底層網路封包解析與實作

## 一、 摘要與研究動機

* **專題目標：** 繞過 OS 網路堆疊，直接呼叫底層 **Raw Sockets**。
* **預期產出：** 實作一款輕量級網路封包監聽程式（微型 Wireshark），探討系統層級權限、二進位解析與 OS 內部行為。

---

## 二、 核心技術與系統 API

本專題高度應用系統程式基礎，核心技術整理如下：

| 核心技術 | 系統 API / 操作手法 | 技術重點與實作目的 |
| :--- | :--- | :--- |
| **原始套接字<br>(Raw Sockets)** | `socket(AF_PACKET, SOCK_RAW)` | 繞過 OS 抽象層，攔截包含 MAC 地址的完整硬體層封包（需具備 `sudo` 最高權限）。 |
| **位元組順序<br>(Endianness)** | `struct.unpack('! ...')` | 解決網路標準（大端序）與電腦 CPU（小端序）之間的系統級資料格式轉換問題。 |
| **位元運算<br>(Bitwise Ops)** | `>> 4` (右移)<br>`& 15` (位元及) | 從單一 Byte 中精準萃取被壓縮的記憶體資料（例如：IPv4 標頭內的版本號與長度）。 |

---

## 三、 系統架構與實作流程

* **開發環境：** Windows + WSL (Ubuntu) 核心，確保完整調用 Linux Kernel 介面。
* **模組化設計：**
  1. `sniffer.py`：主控模組（負責註冊 Socket 與無限迴圈監聽）。
  2. `packet_parser.py`：解剖模組（負責二進位資料剝離）。

**封包解析階層表：**

| OSI 模型階層 | 解析目標範圍 | 提取之關鍵資訊 |
| :--- | :--- | :--- |
| **資料連結層 (L2)** | 封包前 14 Bytes | 來源/目的 MAC 地址、協定類型 (EtherType) |
| **網路層 (L3)** | IPv4 表頭 20 Bytes | 來源/目的 IP 位址、TTL、傳輸層協定編號 |
| **傳輸層 (L4)** | 傳輸層表頭 | TCP / UDP 的通訊埠 (Ports) |

## 四、 實驗結果與特殊現象分析

本系統成功捕捉並解析了實體網路上的 TCP/UDP 流量。此外，在實驗中觀察到一項極具價值的系統底層現象：

### 💡 核心發現：作業系統的內部迴環機制 (Loopback Interface)

* **📌 觀察現象：** 捕捉到大量來源與目的 IP 皆為 `127.0.0.1` 的封包，且其底層的實體 MAC 地址皆顯示為全零（`00:00:00:00:00:00`）。
* **⚙️ 系統原理解析：**
  1. 此現象完美驗證了 OS 的內部網路堆疊（Network Stack）架構。
  2. 當本機軟體互相通訊時，Linux 核心會在**軟體記憶體層級**直接完成封包轉發。
  3. 資料**從未真正離開主機板去觸碰實體網卡晶片**，故無真實 MAC 地址。證明了 Raw Socket 對於核心內部虛擬通訊的強大攔截能力。
